03. NON-NEGOTIABLE DEVELOPMENT RULES
========================================================

1. Build a working application, not just a visual mockup.

2. All major navigation must work.

3. Buttons must perform actual actions.

4. Filters must filter real displayed data.

5. Charts must display meaningful data.

6. Search must work.

7. Tables must support sorting where appropriate.

8. Cards must link to relevant detailed views.

9. Country selection must update the information displayed.

10. The globe must be interactive.

11. The application must not crash when data is unavailable.

12. Never silently fabricate live data.

13. Never present demo data as real-time information.

14. All data must be labeled according to its source,
    timestamp, update frequency, and data status.

15. When an API is unavailable, show a clear unavailable state
    or use clearly labeled sample data.

16. Build modular architecture.

17. Do not put the entire application into a single component.

18. Do not use fake buttons, fake links, or dead UI.

19. Avoid excessive empty space.

20. Avoid unnecessary rounded cards everywhere.

21. Do not create a generic SaaS template.

22. Prioritize actual functionality, visual quality, performance,
    and maintainability.

23. Do not stop after creating the landing page.

24. Continue implementing the major application modules.

25. Run the application, test it, identify problems, and fix them.
